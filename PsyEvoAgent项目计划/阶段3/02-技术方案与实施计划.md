## 模块与职责

新增建议：`frontend/src/features/records/{thoughts,mood}/`、`frontend/src/features/{actions,review}/`、`backend/app/{records,actions,exercises,reviews}/`。Form管理输入和错误，Query管理服务器资源及失效，Router管理范围筛选；不以独立全局store再复制所有服务器数据。

普通工作流处理CRUD、状态转换、日期聚合。Agent仅处理可选想法整理、行动草稿、模拟沟通及文字回顾；输入须含有效grant、资料版本、明确任务和输出schema。输出是 `artifact.proposed`，用户确认通过普通API提交，不要求阶段4的外部工具HITL平台。静态练习不调用Agent。

Meta从阶段2扩展任务类型和资料范围，不能批准用户尚未确认的重要副作用操作。生成失败不影响已保存原文；预算耗尽返回明确未完成草稿状态，禁止重复自动尝试直到得到“积极结果”。

后期角色化只替换图内执行分工，不重写记录CRUD和用户确认接口。本阶段action_proposals/review_drafts继续是独立业务候选；它们的ID/version/source_refs/run/授权关联可供阶段5A Artifact封装，不能因生成角色改变就成为正式记录。阶段5A的Reviewer Agent不是本阶段日历“回顾”功能，Reviewer pass也不等于用户已确认行动或回顾。

### L0调节算法

DependencyAwarePolicyAdapter为确定性模块，输入PolicyCandidates（已批准）、current_need/current_emotion（标注来源与不确定性）、有效Profile或null、偏好和G约束。输出PolicyDecision并绑定run版本。个人画像不能改global policy；策略选择不属于RSI。

```text
adapt(request, candidates, profile, preferences, governance):
    allowed = governance.filter_approved(candidates)
    enforce_fixed_safety_and_explicit_refusal(allowed, request)
    current = explicit_needs_refusals_corrections(request.current_run)
    # 实验配置默认开启画像；来源无效或冲突时只用当前输入。
    if not config.profile or profile is None or profile.stale_or_conflicting:
        concerns = current_only_concerns(current, trend="unknown")
    else:
        concerns = merge_current_and_valid_profile(current, profile, include_counter=True)
    plan = choose_approved_support(allowed, concerns, current)
    return governance.bound_context_budget_and_actions(plan)
```

以上是文档伪代码，不是已部署函数。即时安全判断独立执行，不能在no grant分支被跳过。多个风险共存时先安全/用户拒绝/权限，再当前诉求，再自主性与具体生活影响，最后一般关心；不把风险分数加权相减。用户拒绝某一种方法后仍允许其他可接受支持。

### 行为评测与纵向观察

AgentBehaviorEvaluator除文字外，评该run的结束、记忆读取、按钮/引导、跟进安排和任何通知企图。输出8维：支持有效性、自主性、关系边界、反迎合/事实、依赖状态适配、现实行动衔接、干预体验、安全/隐私；0/1/2为rubric锚点（失败/部分/满足），未知null，不是心理量表分数。严重安全/权限错误单列hard_failures。

LongitudinalOutcomeEvaluator按实验配置进行描述或协议规定的内部分析。随访跳过、失联与撤回分别编码，未观测结果null；消息变少不推断长期有效。没有实际证据不生成因果疗效声明，不增加真人告知或用途审批门槛。

### 当次适配、行为轨迹与自愿纵向观察

S3-T04接L0与行为检查，S3-T06接获准Outcome汇总，S3-T07验证撤回与重复；共同验收S3-A09。调用链：合法当前输入/获准Evidence→Assessor/有效Profile→L0选择→Support→8维行为检查→固定输出→可选反馈/更正→获准纵向Worker。9类风险策略、L0无画像分支和8维0/1/2锚点分别在[阶段目标](01-阶段目标与功能设计.md)、[技术方案](02-技术方案与实施计划.md)维护。

画像按实验配置默认开启；缺有效来源或证据时回退当前输入，用户拒绝与纠正立即生效。明确安全需求独立处理；行为评测覆盖结束方式、记忆读取和跟进企图，未知null，硬失败不能被温暖度抵消。

Outcome按observed/skipped/lost/withdrawn记录；job按owner/window/source_versions/experiment_config_version去重。删除停止相关采集与派生，自评只计一份证据；失访不推断改善。真实执行、历史重放和合成轨迹分别留证，不设额外资格审批。

新增代价为轨迹字段和有界后台汇总；复用现有feedback/actions/jobs，不新建评测平台。失败关闭可选自动调节/分析，保留温暖基础支持、当次偏好、用户新记录与独立CRUD。

## 表与状态

| 表/结构 | 字段与约束 |
|---|---|
| thought_records | owner、situation、initial_thought、feelings、intensity可空、alternative_views、note、status(draft/saved/deleted)、occurred_at/日期精度、source_refs、version |
| mood_records | owner、feeling_tags、value可空、context、occurred_at/timezone、related_refs、version/deleted_at；自评值只作用户记录 |
| action_proposals | owner、source_refs、suggested_title/steps、generator_version、status(pending/accepted/rejected/stale)、version；未接受不写成正式行动 |
| actions、action_steps、action_events | owner、title、reason、due_at/review_at可空、status、difficulty可空、source_refs、version；步骤排序；事件记录前后状态、操作者和时间 |
| exercise_runs | owner、content_id/version、status、started_at/ended_at、可选step_progress/feedback；只在用户选择保存时创建 |
| resource_favorites | owner+content_id唯一；本阶段先用于练习，阶段4扩展文章/方法而不另建收藏系统；收藏不等于授权个人资料 |
| review_drafts | owner、range、source_refs/versions、summary、generator_version、status(draft/reviewed/discarded/stale)、version |

正式行动转换：planned→in_progress/paused/completed/abandoned；in_progress→paused/completed/abandoned；paused→planned/in_progress/abandoned；completed/abandoned如需再次做应创建新行动或显式恢复事件，不通过重发请求覆盖历史。修改状态使用expected_version，保持行与事件同事务；将due_at作为提醒计划不得调用外部通知。

### 版本、参数和异常

PolicyDecision使用总体VersionBinding，另绑定profile_ref/profile_version（无画像时均为null）及user_preference_version，reason_codes有限枚举；profile来源失效/修订后新run重取，正在运行的相关敏感输出取消或重建。策略参数取已批准配置，不接受模型自由设提醒间隔、亲密度、外发行为。无合法支持策略时使用固定安全基线和说明，而非随意拼prompt。

纵向job按owner/window/source_versions去重，耗时评估不阻塞聊天。记录保存成功后分析失败只标分析待处理；不删除用户原始记录。输出检查未通过最多一次有预算修订，之后Controlled Stop。压力测试中notification proposal被固定白名单拒绝，不真的发送。

## API合同

除公开审阅练习内容外均需本人身份，source_refs逐个验证。POST带幂等键；PATCH/DELETE带expected_version；非法状态422、冲突409、不可见404、未获AI读取用途403。列表返回items/next_cursor，单条返回id/version/status和业务字段。

| 方法与路径 | 请求/查询 | 结果与特殊处理 |
|---|---|---|
| POST/GET `/api/v1/thought-records`；GET/PATCH/DELETE `/api/v1/thought-records/{id}` | 上表字段；日期/状态/q/cursor | 记录或删除任务；至少一项有效表达，强度0与空值不同 |
| POST/GET `/api/v1/mood-records`；GET/PATCH/DELETE `/api/v1/mood-records/{id}` | 情绪、自评值/情境、时间；日期/cursor | 原始记录；不返回临床解释字段 |
| POST `/api/v1/run-drafts`，随后POST `/api/v1/runs/{id}/start` | draft的context_type=record_assistance、kind(thought_organize/action_draft/communication/review)、source_refs；绑定grant后start提交input（目标/选择字段）、grant_ids、expected_version | 不要求先建聊天会话；draft未启动不读模型；start返回202相同run_id/version，沿用SSE；产物为候选，取消不写正式记录 |
| POST `/api/v1/action-proposals/{id}/decision` | decision、edited_fields、expected_version | accepted时action_id，其他为拒绝/过期；源变更后409 |
| POST/GET `/api/v1/actions`；GET/PATCH/DELETE `/api/v1/actions/{id}` | title/reason/steps/date/source_refs/版本 | 资源、事件引用或删除任务；手工创建无需LLM |
| POST `/api/v1/actions/{id}/transitions` | to_status、可选feedback、expected_version | 更新资源+event_id；重复提交不重复完成事件 |
| GET `/api/v1/actions/{id}/events` | cursor | 用户可见的状态变更，不提供内部模型推理 |
| POST `/api/v1/exercise-runs`；PATCH/DELETE `/api/v1/exercise-runs/{id}` | content_id/version、保存选择；状态/可选feedback/版本 | 资源或删除任务；未保存练习不隐式补建历史 |
| GET `/api/v1/exercise-runs`；GET `/api/v1/resource-favorites`；PUT/DELETE `/api/v1/resource-favorites/{content_id}` | 日期/cursor；收藏无正文 | 历史或收藏状态；content被撤回时标不可开始；阶段4沿用同一收藏API |
| GET `/api/v1/records/timeline` | from/to、display_timezone、types、cursor | 每日引用列表与计数；按当前权限查询，不落第二套记录副本 |
| POST `/api/v1/reviews`；GET/PATCH/DELETE `/api/v1/reviews/{id}` | POST范围/source_refs只做确定性汇总；PATCH正文/状态/expected_version | 资源或删除任务；PATCH编辑与确认不调用模型，确认后reviewed；来源变更转stale；AI候选统一由record_assistance(kind=review)的draft→grant→start产生并登记review_id |

`artifact.proposed` payload只含artifact_id/type/version及经过授权的预览；确认是业务API真实事务，不依赖模型自然语言“已保存”。候选写请求失败不能把表单关闭并显示成功。

本阶段扩展公共run的record_assistance类型，session_id及会话版本可空，owner与来源授权仍必需。读取资料的顺序为draft→grant→start，不能先启动再补权限。手工行动“草稿”仅保留在当前编辑页面，用户点击确认时才POST创建planned行动；离开未保存时提示放弃，不默默建一条正式行动。AI行动草稿使用action_proposals并保留独立确认流程。

练习使用阶段1版本化静态内容清单中的稳定content_id。阶段4迁到内容表时保留ID和版本；`/api/v1/exercises/{id}`作为练习读取入口，复用统一内容读取服务，不形成另一份可发布正文。新开启或恢复练习前核对内容状态；撤回后停止继续提供步骤、允许退出，已保存的本人体验记录保留但不透出撤回正文。

## 时间与日历计算

时间点记录保存UTC、原IANA时区及精度；显示时按用户当前选择的display_timezone分日。仅日期记录保持其原始日期，不假造零点。睡眠按用户选择的entry_date显示并明确“记录的哪一天/哪晚”，入睡跨度另用完整起止计算；未知日期进入未注明日期分组。阶段2录入的值不能被当前时区静默改写。

回顾先使用确定性SQL/服务聚合，所有统计同时返回期间、纳入类型、条数和缺失数。AI只能读取用户本次选择且当前仍有效的来源。源版本变化或删除后候选过期，已保存回顾标stale并清理不能保留的派生正文；引用当前不可用时不以旧缓存兜底。

## 本阶段核心逻辑实体与合成片段

共同字段、类型、枚举及VersionBinding由[共同合同](../阶段1/02-技术方案与实施计划.md#shared-contracts)统一维护。下表仅列专属字段；复用既有表/注册表，不新增第二份事实库。

| 实体 | 专属字段/枚举与关联 | 隔离、敏感性和删除关系 |
|---|---|---|
| PolicyDecision | run_id、candidate_policy_refs、selected_mode、adjustments、reason_codes、profile_ref/null、user_preference_version、VersionBinding、allowed_context、stop_reason | 只能选已批准策略；reason公开为简短说明，不能泄露隐私推理链 |

| OutcomeObservation | owner或研究pseudonym、observed_at、window、self_chosen_goal、autonomy/support_help/interference、followup_status=observed/skipped/lost/withdrawn、exposure/measurement_mode | 失访未知；观察性变化不冒称因果；用户可拒绝后续采集 |

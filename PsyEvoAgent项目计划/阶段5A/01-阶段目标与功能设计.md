## 阶段目标与进入条件

PsyEvoAgent前期以单Support Agent完成最小可靠闭环；在Memory、RAG、Tool、Eval、Trace等基础能力稳定后，必然演进到基于同一LangGraph Runtime的受控Multi-Agent架构。Multi-Agent是确定的后期架构目标，不是可选实验，也不要求每个请求调用多个Agent。

本阶段正式增加F-MA-001（内部架构能力），并增强F-CHAT-001、F-MEM-001/002、F-TOOL-001、F-EVAL-001和F-OPS-001。开始实现前，阶段1～5的Support Agent、Meta路由、LangGraph、Structured Output、RAG、Memory、Tool、Budget、Cancellation、Trace与统一Eval须达到各自依赖门槛。不得通过提前拆出大量Agent替代前四阶段的基础建设；本阶段不以已经公开上线为前提。

Eval不决定项目是否采用Multi-Agent，而决定角色组合的适用场景、收益门槛、调用预算和降级策略。未经证明有收益的组合不得进入默认执行路径，但仍需完成角色能力、隔离、预算、恢复和可评价性的工程验收。

## 正式角色与职责

| 角色 | 输入与职责 | 产物及不可越过的边界 |
|---|---|---|
| Support Agent | 当前任务、明确偏好及获准最小上下文；倾听、澄清、合作分析、支持方式选择、行动建议、自然收尾，整合证据和复核意见 | SupportDraftArtifact；是主要且唯一负责最终心理支持表达的Agent；不自行扩张权限或批准业务写入 |
| Evidence Agent | 获准的问题和资料域；判断并执行授权检索、RAG、资源查询，整理来源、结构化证据及证据不足 | EvidenceArtifact，含provenance/citation所需引用；不替代Support表达，不向用户直接发送检索文本，不扩张资料权限 |
| Reviewer Agent | 指定版本的Support草稿、相关证据、用户明确拒绝及核验所需最小授权信息；按固定检查类别独立复核 | ReviewArtifact内的ReviewDecision；不自由聊天，不修改用户资料，不充当独立evaluator或发布审批者 |
| Memory Workflow | 实验配置开启的候选提取任务与本人有效来源；复用阶段2的LangMem与候选服务 | MemoryCandidateArtifact；不是第二个memory store；业务服务校验后自动保存正式记忆，角色不决定数据用途或修改授权 |

Reviewer固定检查类别：事实与感受混淆、猜测第三方意图、过度迎合、未经支持的诊断、违反明确拒绝、来源无效的记忆、虚构或不可访问引用、越权Tool、过强建议、遗漏必要现实支持、违反固定风险/安全规则。独立复核指单独角色与调用、独立输入合同，不意味着模型判断天然正确或具有专业资格。

## 按任务调用，不固定全链路

```text
普通倾听、澄清或简单支持
  Meta → Support → Output Policy → 用户

需要事实或知识支持
  Meta → Support提出检索需求 → Meta核验 → Evidence → EvidenceArtifact
       → Support整合 → Output Policy → 用户

需要独立复核但不需要检索
  Meta → Support草稿 → Reviewer → 经核验的Support稿 → Output Policy → 用户

高价值或高风险复杂回答需要证据及复核
  Meta → Support → Evidence → Support草稿 → Reviewer
       → 最多一次Support修订 → 必要的第二次Reviewer及确定性检查
       → Output Policy → 用户

涉及长期记忆候选
  授权来源 → Memory Workflow / LangMem → candidate
       → 来源 / grant / schema / 版本检查 → 业务事务自动保存正式memory
```

所有委派都经过Meta决定与LangGraph Coordinator执行；Support可以提出需要Evidence的请求，但不能直接扩大allowed_agents或allowed_tools。Meta不是Agent，也不意味着每轮必须额外调用一次LLM；不新增Supervisor LLM取代Meta。Memory Workflow按实验配置在有有效来源与预算时提取；无需逐条同意，推断始终保留标识。

Reviewer必须复核的任务不允许因为超时而直接发布未审草稿；采用预定保守输出或Controlled Stop。Reviewer被关闭或证据不足均不能关闭固定安全规则、已审现实支持说明或基础求助入口；急切支持不能被循环审稿拖延。80%单Support、15%Support+Evidence、5%三角色仅是路由比例示例，不是已测结果或固定配额。

## 学生端与内部工作台

学生仍使用“对话｜我的记录｜支持资源｜我的”，不增加单Agent、Multi-Agent、Reviewer或角色选择菜单。必要状态显示为“正在查找经过审核的资料”“正在核对来源”“等待你确认修改”；不把内部角色名作为宣传语，也不显示Chain-of-Thought。

内部复用阶段5的工作台：

| 现有页面 | 本阶段增加的可观察内容 | 访问边界 |
|---|---|---|
| `/workbench/operations`运行详情 | 本run角色集合、结构化路由原因、调用次数、handoff、Artifact引用、Reviewer verdict、revision次数、各角色latency/token/cost、失败、最终stop reason | 默认仅元数据；Artifact正文须另有来源及用途权限；不因ops角色取得学生全文 |
| `/workbench/evaluations` | MA-A/B/C、知识路径消融及配置开启且来源有效时的MA-D对照，逐场景收益/错误/成本与启用决定 | 使用同一数据和预算口径；保留失败及未启用组合 |
| `/workbench/versions` | 图与Artifact schema、角色prompt、路由及预算策略版本、准入证据和回退目标 | 人工发布门禁；单次run固定版本，回退不恢复旧用户数据 |

继续复用OTel、Langfuse和既有评价服务，不另建Dashboard、编排平台或观测主存。观测故障显示不可用而非零错误；不得阻塞主对话或泄露未授权资料。

## 两条阶段演示旅程

1. 同一版本处理倾听、知识查询、复杂支持和记忆提取：简单请求仅Support，知识请求附来源，复杂稿有结构化复核；记忆提取校验后自动保存，保留推断标识，学生界面不增加用途或角色选择。
2. 在隔离装配注入失效来源、Reviewer超时、并行检索一支失败、预算耗尽和撤权：系统保留有效结果、阻断不合法输出并有限停止；工作台可追踪原因，重启不重置预算或重复业务副作用。

## 阶段完成与后续衔接

阶段5A须交付可运行的按需角色图、typed Artifact、最小上下文、预算/取消/恢复合同、专项Eval和现有工作台增强，并取得原S5A-A01至S5A-A14及新增S5A-A15的实际工程证据；文档存在不算能力已经稳定。默认路由只采用通过事前门槛的组合，未达标组合记录原因、关闭范围和后续改进项，不将其解释为取消Multi-Agent目标。所有组合尚未达标时不得声称多角色默认路由已获准。

阶段6在此稳定能力上优化角色提示、路由、handoff、触发条件、上下文及预算分配，不改权限、确认、删除、安全或评价器。阶段7仍研究改进方法本身，开始前必须已有本阶段稳定能力和阶段6固定改进器；不把首次搭建Multi-Agent当作RSI成果。实验访问与内部评测按配置推进，不设年龄或用途审批；实际发布、外发仍需操作授权。

## 工程能力与用户价值

F-MA-001/F-EVAL-001/F-OPS-001；U14。简单请求保留单Support；复杂任务的证据与有限复核可追踪，等待/停止仍使用同一公共事件。失败分支不覆盖有效结果，必要复核失败不发候选正文。

继续维护角色最小上下文、typed Artifact、原子预算、review/revision上限、partial result和恢复；阶段5只补双向评测。MA组合仍按独立Eval准入，保留S5A-A01～S5A-A14并新增S5A-A15；正式依赖5A→6→7。
